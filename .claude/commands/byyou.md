# /byyou — Напівавтономний потік («heart attack»)

> **Що це:** режим де Claude бере ціль, планує на 10-15 кроків і **виконує сам потоком**, зупиняючись лише на брамах і важливих рішеннях. Роман контролює результат, не кожен крок.
> **Скоуп:** тільки проект NeverMind. Стан потоку — `_ai-tools/BYYOU_PLAN.md`. Рішення «чому» — `docs/adr/`.

**Коли використовувати:**
- Роман дав велику ціль (≥3 файли або ≥1 год) і хоче «постав і відійду».
- НЕ для дрібниці <30 хв — там звичайний діалог або `/fix` швидші.

**Аргументи:**
- `/byyou <ціль>` — нова задача (планую → беру ОК → йду сам).
- `/byyou` без аргументу — **продовжити** незавершений потік з `BYYOU_PLAN.md`.

Подумай. Пошукай додаткову інфу в інеті якщо треба. Придумай системне сильне стабільне рішення. Враховуй план, враховуй майбутні задачі.»**

## 🚦 Дві брами (єдині обовʼязкові зупинки)

1. **Старт** — показую план 10-15 кроків → чекаю ОК Романа → тільки тоді потік.
2. **Деплой** — між брамами **тільки локальні коміти, БЕЗ push**. Push (=живий деплой) лише коли Роман скаже релізне слово **«деплой»**. Це стереже хук `byyou-push-lock.js` — поки `BYYOU_PLAN.md` active, push заблоковано без «деплой».

## 🎚️ Три стани кроку (прості слова, не traffic-light для девелопера)

- 🟢 **GO** — роблю сам (читання/код/тест/локальний коміт).
- 🟡 **ТВІЙ ХІД** — потрібен смоук на iPhone або думка Романа.
- 🔴 **СТОП** — спершу питаю: архітектура / зміна схеми даних / новий storage-ключ / зміна payload `nm-data-changed` / незворотне / суперечність з ROADMAP чи DO_NOT_TOUCH.

## 👁️ Видимість: Роман бачить кожен крок

Роман хоче **бачити що я роблю** (не працювати «у тиші»). Тому:
- **Кожне повідомлення у режимі починається маркером** `[/byyou N/M]` (крок N з M) — щоб завжди було видно що режим активний і де ми.
- **Перед кожним кроком — короткий рядок «що роблю»** (1 речення, простими словами). Не простирадло, але видно дію.
- **Пульс після кроку** — що зробив + коміт + наступне.
- Зупинка з питанням (🟡/🔴) — окремо й помітно.

## ⏸️ Контекст-запобіжник — СТОП на 75%

Це стереже **хук `byyou-context-guard.sh`** (Stop-подія), НЕ моя памʼять — бо під час потоку `context-warning.sh` не спрацьовує (він лише на ввід Романа), а дисципліна на високому контексті деградує:
- Після кожного мого ходу при **≥75%** хук робить `exit 2` — **блокує тихе завершення**, я ЗОБОВʼЯЗАНИЙ обробити (не згортатись передчасно — клас «context anxiety»).
- **Моя дія на блок:** 1) дозаповнити `BYYOU_PLAN.md` «Де зупинились» ПОВНІСТЮ (це handoff для нового чату), 2) `Статус: paused`, 3) окреме помітне 🛑-повідомлення Роману, 4) зупинитись. Після `paused` хук розблоковує (active-гейт перестає матчити).
- Бекап: `/cc` ручна звірка + `context-warning.sh` на ввід Романа.
- **Помітне повідомлення Роману** (власним повідомленням, не в рядку пульсу):
```
🛑🛑🛑 КОНТЕКСТ 75% — ЗУПИНЯЮ /byyou 🛑🛑🛑
Стоп на кроці N/M · стан збережено у BYYOU_PLAN.md
→ Відкрий НОВИЙ чат і напиши «/byyou» — підхоплю рівно з цього місця.
```
- **Чому 75%, а не під завʼязку:** лишаю запас на чистий `/finish` + збереження стану. На високому контексті вони систематично летять (урок SK6E2) — тому стоп раніше, з запасом.

## Фаза 1 — Планування (тільки NEW)

1. **Читаю реальний код** усіх залучених файлів (Read/Grep) — не на памʼять.
2. Якщо ціль = нова фіча → **дослідження** (WebSearch/WebFetch: аналоги, best practices). Якщо баг → 3 діагностичні питання (корінь / масштаб / DRY).
3. Якщо ціль зачіпає `src/core/*` / схему localStorage / payload / >3 файли / >500 рядків → **Council 5 агентів** (read-only, `model: "sonnet"`).
4. Зважую проти принципів Романа: найпростіше=найкраще · корінь не симптом · мінімум у фічах/повно у фундаменті · детерміноване → парсер у `src/data/`, не промпт.
5. Складаю 10-15 кроків у `BYYOU_PLAN.md` (таблиця кроків + маркер 🟢/🟡/🔴 кожному). Кроки що зачіпають архітектуру/схему/storage → одразу 🔴 (виявити ЗАРАЗ, не на кроці 6).
6. Ставлю **Статус: active** у `BYYOU_PLAN.md` (вмикає push-замок).

**→ 🚦 Брама старту:** показую план Роману (≤20 рядків) + питання «Стартуємо? (так / зміни крок N / скасуй)». **Чекаю ОК. Без ОК — стоп.**

## Фаза 2 — Потік (петля по кроках)

Для кожного кроку:
1. **Читаю код у точці зміни** — навіть якщо «вже читав цей файл раніше у сесії» (захист від дрейфу: файл міг змінитись моїми Edit).
1.5. **Різ/перенос коду між файлами → мапа ЗОБОВ'ЯЗАНА містити константи + змінні модуля, не лише функції.** Урок E2E #39 (батч D): агент-розвідник змапив функції, константи лишились у старому файлі → перенесена функція мовчки крашила вкладку (ReferenceError — звертання до змінної якої нема). У промпт розвідника явно: «перелічи ВСІ top-level const/let на які посилається кожна функція». Після переносу: grep кожного ідентифікатора з перенесеного блоку у новому файлі.
2. **Роблю:** файл >250 рядків → skeleton+Edit частинами; нові UI-рядки → `t('key','fallback')`; зміна `src/*` → bump `CACHE_NAME` у `sw.js`.
3. **Перевіряю:** `node --check <файл>`; якщо чіпав UI-елементи → `npx playwright test --list` (парс). Контракт-тести (`scripts/` або `tests/`) де є.
4. **Локальний коміт** (БЕЗ push): `feat(<area>): крок N — <опис> [byyou]`.
5. **Оновлюю `BYYOU_PLAN.md`:** крок ✅ + hash коміту + поле «Де зупинились».
6. **🔴/🟡 крок** → зупиняюсь, питаю Романа, чекаю. **2 невдалі спроби фіксу поспіль** → Pre-mortem → стоп, питаю (не патч на патч).

**Пульс** (щокроку, коротко — Роман бачить прогрес):
```
🟢 [4/11] Парсер дат інтегровано · abc1234 · далі: 5 — i18n
```

## Фаза 3 — Тест-батч (у кінці логічного блоку)

1. Заповнюю **Реліз-нотатки** у `BYYOU_PLAN.md`: ЩО ЗМІНИЛОСЬ / **ЩО МОЖЕ ЗЛАМАТИСЬ** (міні pre-mortem) / ЩО ПЕРЕВІРИТИ НА IPHONE (≤5, те що ВИДНО на екрані, без назв коду).
2. Якщо у блоці нові `data-action` / `id="*-modal"` / поля / вкладки → додаю/оновлюю тест у `tests/e2e/*.spec.js` (правило 13 CLAUDE.md).
3. Показую реліз-нотатки Роману.

## Фаза 4 — 🚦 Брама деплою

1. **Pre-flight ПЕРЕД пушем** (ловити до прода, не після): прогнати всі `node scripts/check-*.js` (контракт-тести + cyrillic-boundary) + `npx playwright test --list` (парс). Червоне — фіксую, не пушу.
2. Кажу: «Блок готовий. Реліз-нотатки ⬆️. Сказати "деплой" — запушу.»
3. Після **«деплой»** від Романа: **відкриваю вікно self-correction** — створюю маркер `.claude/.byyou-release` → `git push` (retry 2s→4s→8s→16s).
4. **Петля E2E + self-correction через GitHub MCP** (я сам, Роман не лазить у GitHub):
   - `mcp__github__actions_list` (e2e.yml, гілка) → run_id найновішого; чекаю завершення (фоновий таймер ~3 хв).
   - `success` → **видаляю маркер** → «E2E ✅. Деплой v{N}.» → наступний блок / Фаза 5.
   - `failure` → `get_job_logs` (failed_only) → читаю сам → діагностую КОРІНЬ → фікс → **перепуш БЕЗ повторного «деплой»** (вікно відкрите) → знову петля. Романові — лише коротко: що було червоне і що пофіксив, не кожен раунд.
   - timeout → «E2E ще біжить» і йду далі.
5. **Ремонт затягнувся (3+ раунди) або корінь поза блоком** → стоп, видаляю маркер, звітую де застряг.

> **Вікно self-correction:** Роман схвалює деплой блоку ОДИН раз; ремонти CI того ж блоку — мої, без повторних «деплой». Між блоками маркера немає → замок знову вимагає твого слова. Це знімає тертя, але не послаблює захист від випадкового пушу.

## Фаза 5 — Вихід / Звіт

1. Підсумок Роману: зроблено (кроки+hash), що відкрито, наступний крок.
2. Архітектурні рішення з потоку → короткий ADR у `docs/adr/`.
3. `Статус: done` у `BYYOU_PLAN.md` → архівувати у `_archive/BYYOU_PLANS_archive.md`, живий файл скинути у шаблон (idle).
4. Викликати `/finish` (UPDATE) — оновити SESSION_STATE / ROADMAP / CHANGES.

## 🚪 Вхід / вихід з режиму + стоп-слово

**Як видно що режим активний:** `BYYOU_PLAN.md` статус `active` + кожне моє повідомлення з маркером `[/byyou N/M]`.

**3 способи вийти:**
1. **«стоп»** (або «вийди», «пауза», «досить») → **негайно зупиняюсь**, зберігаю стан (`Статус: paused`), вся робота лишається. Кажу явно: «🏁 Вийшов з /byyou на кроці N. Робота збережена, `/byyou` продовжить.» Повертаюсь у звичайний режим (push-замок зніметься коли статус не active... — лишаю `paused`, замок діє доки не завершимо чи не скинемо).
2. **Авто-вихід** — коли план виконано (Фаза 5): сам виходжу зі звітом «🏁 /byyou завершено».
3. **«відкат» / `/abort`** → стоп + пропоную відкат до мітки `byyou-start-<сесія>` (яку ставлю на Брамі старту): `git reset --hard byyou-start-<сесія>`. **reset --hard лише з явного підтвердження Романа.** Якщо нічого не пушилось — відкат безпечний (втрачаються лише локальні коміти, що й треба).

**Завжди оголошую вхід і вихід явно** — Роман ніколи не плутається активний режим чи ні.
