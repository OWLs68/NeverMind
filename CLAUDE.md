## 🎯 Що це за проект

Персональний PWA-агент продуктивності. Ключова ідея — **мінімальне тертя**: користувач пише в Inbox, AI (GPT-4o-mini) автоматично визначає тип запису і розподіляє по вкладках.

- Стек: ванільний JS, localStorage, GitHub Pages, без фреймворків і бекенду
- API: OpenAI GPT-4o-mini (ключ у localStorage `nm_gemini_key` — тимчасово; після Supabase — ключ на сервері, юзер не бачить)
- Деплой: автоматичний через GitHub Actions при пуші у feature-гілку `claude/**`
- Мова: українська (UI + AI-промпти)

## 🧠 Поведінкові правила (діють завжди)

1. **БЕЗ «Роби» — не чіпати код.** Тільки обговорення до явного підтвердження від Романа.
2. **Один баг за раз.** Після виправлення — пропоную наступний.
3. **Читай код перед змінами.** Ніколи на пам'ять. Глибина важливіша за швидкість («краще одна якісна відповідь ніж три поверхневі»).
4. **Сперечайся з аргументами.** Чесність > ввічливість. Коли мій варіант об'єктивно кращий — стверджуй чітко, не ховайся за «вирішуй ти». Деталі і коли НЕ нагліти → `RULES_WORKFLOW.md`.
5. **Корінь vs симптом.** Якщо 2-3 спроби лагодити одне і те ж не дають результату — крок назад: «а проблема та?». Не патч на патч на симптом. Урок з 01.05 (6ANWm): ціла сесія на лагодження хука, корінь був у структурі документації.
6. **Сигнали болю Романа** («простіше / коротше / не розумію / простирадло / не читаю / скороти») → визнати + переписати простіше + БЕЗ преамбули («Зрозумів / Прийнято / Записав»).
7. **Розмір відповіді — середній або менший.** 5-15 рядків для звичайної. Не мікро-відмашка, не простирадло. Чітко, по суті, без води.
8. **Пояснення в дужках для незнайомих кодів** (snake_case/camelCase назви, CSS-властивості, новий жаргон) — щоразу, не один раз. Загальні слова (`push`, `pull`, `week`, `commit`, `update`, ID сесій, хеши) — НЕ пояснюй. Деталі і колонки ✅/❌ → `RULES_COMMUNICATION.md`.
9. **UI-задачі — ВИГЛЯД на екрані, не назви коду.** «Фіолетовий фон», «їде за пальцем» — а не `overflow-y` чи `#7c3aed`. Деталі → `RULES_UI.md`.
10. **Чекай плану перед кодом.** Опиши що зміниш, чекай ок.
11. **i18n: усе нове UI обгортай у `t('key', 'fallback')`.** Готує застосунок до інших мов після Supabase — словник перекладів просто замінить fallback. Whitelist (НЕ обгортати): `src/ai/*` промпти, `src/owl/*` mixed AI+UI, console-логи, коментарі, канонічні назви даних. Workflow + детектор `check-i18n.js` → `_ai-tools/RULES_TECH.md` §4.
13. **E2E-тести синхронні з UI — додав кнопку/модалку = додай тест.** (Hetzner-тестер замінено на Playwright у CI, foyz2r 16.06.2026; старий → `_archive/hetzner-tester/`). Тести у `tests/e2e/*.spec.js`, фундамент `tests/e2e/helpers.js` (`boot`/`seedState`/`mockAI`/`gotoTab`), запуск на кожен push безкоштовно через `.github/workflows/e2e.yml` (движки Mobile Safari WebKit + Desktop Chrome). Коли у сесії додаєш/змінюєш: (а) кнопку `data-action`, (б) модалку `id="*-modal"`, (в) поле `id`, (г) вкладку/sub-tab — ПЕРЕД `/finish`: 1) додати тест у відповідний `*.spec.js` за патерном існуючих (assertions на ЕКРАН: `toBeVisible`/текст, НЕ localStorage), 2) `npx playwright test --list` локально (парс), 3) після push звірити зелений E2E через GitHub MCP. AI behavior (тон OWL, галюцинації) — НЕ автоматизується, Roman сам. iOS-quirks (rubber-band/backdrop/свайп) — headless НЕ ловить, manual smoke на айфоні.

12. **Перш ніж лоскутити промпт — питай: це детерміноване чи природна мова?** (записано 64CXo 10.05). Дати/числа/конкретні слова/класифікація момент-vs-задача-vs-подія = **детерміноване** → одразу парсер у `src/data/` або code-side guard у dispatcher, БЕЗ покладання на AI. Природна мова (тон, переказ, емоції, творчий текст) = AI з промптом. NeverMind за статистикою — >50% детермінованих задач, тому промпт-лоскути марнують години. Підтверджений кейс 64CXo: 3 раунди промпт-фіксів («вчора» → дейлі-папка) провалилися, поки не написали `src/data/ua-time-parser.js` (12/12 тестів пройшло одразу). Промпт додавати ОСТАННІМ — як підказку AI коли викликати code-path. Правильний порядок: **парсер/whitelist (5) → code-side guard (6) → декомпозиція (7) → контекст AI (4) → tool description (3) → промпт (2-1)**.

  - рефакторинг файлу >500 рядків
  - зачіпає >3 файли одразу

**Як працює:**
1. Перед запуском пишу Роману: «🧠 Запускаю 5 поглядів... зачекай хвилину» (щоб знав про паузу)
2. Один meседж — 5 паралельних `Agent` викликів з ролями: 🕵️ Критик / 🌀 Стратег / 🚀 Оптиміст / 💎 Свіжий погляд / 🛠 Виконавець. Кожен сам читає код через Read/Grep — справжні якорі, не галюцинації.

4. Романові: фінальний план + якщо знайшли реальну дірку — окремий рядок «⚠️ [Роль]: знахідка у `file.js`»

**Чого тут НЕМАЄ:** жодного логу, метрик 👍/👎, граматичних рамок, тріад незворотності. Якщо механізм працює — лишається. Якщо тільки тратимо токени — викидаємо. Тестуємо на реальних задачах, не паперах.

## 🧠 4 mental models — методики прийняття рішень (коли застосовувати)

> Записано LfA6w 08.05.2026 за пропозицією Романа (Instagram-пост @ira.and.ai). Систематизує те що ми робимо інтуїтивно у Council/Gemini-раундах. **Це не нові інструменти — це нагадування коли пере́мкнутись з точкових фіксів на стратегічне мислення.**

### 1. Pre-mortem (Гері Кляйн) — «Уяви що провалилося. Чому?»

**Тригер:** перед фіксом #2 одного бага у тій самій точці. Або перед великим Edit'ом >50 рядків. Або перед стартом архітектурної фази.

**Питання собі:** «Якщо через 1 годину/тиждень цей фікс зламався — що саме пішло не так?» Якщо знаходиш 2-3 правдоподібні шляхи провалу — спершу backup snapshot або Council, потім код.

**Підтверджений кейс LfA6w:** перед переписуванням 5 файлів промптів зробив `cp src/* _archive/prompts_backup_LfA6w/*.bak`. Коли AI почав робити дубль — швидкий відкат був готовий.

### 2. Inversion (Чарлі Мангер) — «Як гарантовано це зламати?»

**Тригер:** перед великим коммітом >3 файли або >50 рядків. Перед промптом-перепису.

**Питання собі:** «Перерахуй 5 способів гарантовано зламати цю фічу/промпт/міграцію». Якщо знаходиш сценарії — додай code-side guard або переформулюй промпт ДО deploy.

**Анти-кейс LfA6w:** переписав CHIP_PROMPT_RULES → задеплоїв → AI почав робити дубль save_finance+save_task. Якби зробив Inversion (`«як AI може зламатись на batch tool_calls?»`) — побачив би це до деплою і одразу додав би code-guard.

### 3. Red Team (військова + кібербезпека) — «Атакуй свій план поглядом конкурента»

**Тригер:** перед deploy критичної фічі. Перед стартом нової субсистеми (Supabase, Voice, Email Bridge). Перед `/finish`.

**Інструмент:** Council 5 паралельних агентів через `Agent` tool — Sonnet model. Промпт: «Ти консультант який має знищити цю архітектуру. Знайди вразливості». Уже існує як механізм — використовувати ПРОАКТИВНО, не тільки коли Роман каже «дивись ширше».

**Підтверджений кейс LfA6w:** після того як Роман сказав «з промтами біда» — запустив 2 паралельні агенти (audit + architect) + 3 ітерації Gemini = знайшли 4 кореневі проблеми перш ніж переписувати.

### 4. 10-10-10 (Сьюзі Уелч, ex-HBR) — три часові горизонти

**Тригер:** перед архітектурним рішенням (Supabase, tool consolidation, новий модуль). Перед записом нової ідеї у ROADMAP як Active.

**Питання собі:**
- **10 хвилин** — чи дасть це юзеру миттєву цінність?
- **10 місяців** — чи створює це тех-борг для майбутніх сесій? Чи спрощує добавлення наступних фіч?
- **10 років** — чи відповідає це візії Jarvis-агента або це лоскут на сьогодні?

**Анти-кейс LfA6w:** додавав CHIP_PROMPT_RULES правила за лоскутом 10+ разів за тиждень. Якби робив 10-місячний горизонт — побачив би що це накопичується у незахисний борг → одразу пішов би на decision-tree рефакторинг.

### Як використовувати у щоденній роботі

- Не «обов'язково перед кожним коммітом» — так стане бюрократією як COUNCIL_CONCEPT 4-ітерація.
- А **тригер-based:** коли симптом матчить — Голова перемикається у відповідну модель **ДО** першого Edit'у.
- Найголовніше — **Pre-mortem перед 2-м фіксом одного бага**. Це найчастіший провал процесу.

## 🚀 Архітектура «Один мозок на все»

OWL = єдиний Jarvis. Табло, чати, чіпи — різні «вікна» одного мозку. Якщо щось відбувається у застосунку і OWL про це не знає — це баг.

**🚨 Принцип «8 чатів = ОДИН мозок» (PJi7l + 64CXo):** Inbox / Tasks / Notes / Me / Evening / Health / Finance / Projects — це 8 ПРИЗМ одного агента, не 8 окремих систем. Будь-яка зміна tool / handler / правила автоматично діє у ВСIХ чатах. Антипатерн «у Tasks працює, у Notes — ні» = баг архітектури, не feature. Деталі реалізації + чек-ліст «зачіпаю AI — перевір 8 чатів» → `_ai-tools/RULES_TECH.md` §2 + `_ai-tools/RULES_WORKFLOW.md` §2.

Повна візія + поточна реалізація (`nm-data-changed` dispatch) + план розвитку → `NEVERMIND_LOGIC.md`.
