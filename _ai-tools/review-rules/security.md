## 🎯 Наш профіль загроз (шукати ЦЕ першим)

- **XSS через innerHTML** з юзер-даними без `escapeHtml` (реальний клас: notes.js
  preview, folder desc — Sec-Issue #9). `data-*` → ЗАВЖДИ escapeHtml, НІКОЛИ
  escapeJsArg (B-197).
- **Ключ OpenAI у localStorage** (`nm_gemini_key`) — новий шлях витоку (лог, нове
  місце передачі у plaintext, error що друкує headers) = HIGH. Корінь-фікс =
  Supabase Edge Function (roadmap), до того — не додавати нових точок витоку.
- **Prompt injection** з юзер-контенту (назви папок/проектів, текст моментів →
  системний промпт). Захист: `ANTI_INJECTION_RULE` у промпті + передавати
  юзер-дані у user-позицію, не system. Нова конкатенація юзер-тексту в system = прапор.
- **\b-кирилиця** у guard-регексах (клас закрито, але новий regex у security-коді
  = перевір; сторож check-cyrillic-boundary стереже).
- **CI-інʼєкція:** github-контекст (`github.ref_name`, inputs, PR-тіло) прямо у
  `run:` shell → через env, ніколи в інтерполяцію.
- **Секрети у логах хуків/CI/JSONL-журналі** — маскувати ключі/PAT.

## 🚫 НЕ репортити (адаптовані hard-exclusions — анти-шум)

1. DoS / вичерпання ресурсів / rate-limit. **ВИНЯТОК:** необмежені LLM-виклики
   без cost-cap = фінансовий ризик (Phase 7), НЕ DoS — репортити.
2. Ключ на диску якщо ЗАШИФРОВАНИЙ/захищений. (У нас незашифрований у localStorage —
   це відомий борг, репортити лише НОВІ шляхи витоку, не сам факт.)
3. Race conditions без конкретного шляху експлуатації (наші «дві вкладки одночасно» —
   репортити лише якщо веде до втрати даних юзера, не теоретично).
4. Валідація не-security полів без доведеного impact.
5. Відсутнє «загартування» (missing best practice) — репортити КОНКРЕТНУ дірку,
   не «немає X». **ВИНЯТОК:** unpinned GitHub actions = конкретний ризик.
6. Client-side JS не потребує auth — це робота сервера (актуально після Supabase).
7. Insecure randomness у НЕ-security контексті (UI-id через crypto.randomUUID — ок).
8. Юзер-контент у user-позиції AI-розмови — це НЕ prompt injection (лише system-позиція).
9. Логування не-PII — не вразливість. Логування секретів — вразливість.
10. Безпека у `*.md` — крім `.claude/**` (це виконуваний промпт-код, не документація).
11. UUID незгадувані — не флагати «відсутню валідацію UUID».
12. Regex-складність у коді що НЕ обробляє недовірений вхід.
