# ADR-001: Режим `/byyou` (напівавтономний потік) + push-замок

**Дата:** 20.06.2026 · **Сесія:** gfrvu5 · **Статус:** прийнято

## Проблема
Зараз робота з Claude — мікроконтроль: правило «без слова Роби — код не чіпати» = підтвердження майже кожного кроку. Роман хоче віддати рутину: Claude планує на 10-15 кроків і йде сам, а на Романа лишаються тільки базові/важливі рішення.

При цьому **кожен push у `claude/**` деплоїться у живий застосунок одразу** (auto-merge → GitHub Pages). E2E-тести деплой **НЕ блокують** (біжать паралельно, лише звітують — перевірено у `.github/workflows/auto-merge.yml`). Тобто головний ризик автономного режиму — не погане рішення Claude, а **випадковий прод-деплой**.

## Варіанти (безпека деплою)
- **A — E2E блокує деплой.** Відкинуто: headless Playwright не ловить ~90% iOS-quirks (свайпи/клавіатура/safe-area), тож блокував би хороші релізи і все одно пропускав би iOS-баги. Gemini раунд 2 влучно назвав це пасткою.
- **B — Стейджинг `/dev/` підпапка** (Gemini+GPT раунд 2, обидва поставили #1). Відкинуто ДЛЯ ЗАРАЗ: `localStorage` спільний на весь домен (per-origin, не per-path) → тестова версія читала б і псувала б **реальні** дані Романа. Чистий стейджинг можливий лише коли дані переїдуть на сервер → **Supabase-ера**.
- **C — Push-замок на слові Романа.** Обрано.

## Рішення
1. Скіл `.claude/commands/byyou.md` — 2 брами (Старт: план→ОК; Деплой: push лише з дозволу), стан у `_ai-tools/BYYOU_PLAN.md`, маркери GO/ТВІЙ ХІД/СТОП, петля E2E через GitHub MCP, реліз-нотатки, `/abort`.
2. Хук `.claude/hooks/byyou-push-lock.js` — поки `BYYOU_PLAN.md` active, `git push` заблоковано доки Роман не скаже **«деплой»** у своєму повідомленні (хук читає USER-повідомлення транскрипту — Claude підробити не може).
3. Тестовий шар (контракт-тести конвеєра з замоканим OpenAI + Golden Journey) — окремо, як **перша задача в самому /byyou** (обкатка на собі, Варіант А).
4. `BYYOU_PLAN.md` (жива задача) розділено від `docs/adr/` (довгі рішення) — обидва лишаються маленькими.

## Чому
- Push-замок детермінований і Роман-керований — закриває ризик №1 без переробки CI і без ризику для реальних даних.
- Тести «мислення» (не кнопок) важливіші для NeverMind через правило «детерміноване ≠ промпт» — тестуємо парсер→намір→конверт, OpenAI мокаємо.
- Відкинуто бюрократію (бюджет автономії, числовий risk-score) — для одного юзера це антипатерн (урок COUNCIL_CONCEPT).

## Переглянути коли
Перехід на Supabase: тоді (а) стейджинг `/dev/` стає безпечним (окремі дані) → варіант B повертається; (б) push-замок можна доповнити справжнім стейджинг-промоутом; (в) контракт-тести розширити на server-side конвеєр.
