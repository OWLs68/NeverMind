# ADR — Architecture Decision Records (рішення «чому»)

> **Що це:** короткі записи важливих рішень — щоб через пів року не копати чати Claude питанням «а чому тут так?».
> **Коли писати ADR:** рішення важливе **довше ніж до кінця задачі** (схема даних, sync-стратегія, вибір технології, незворотний компроміс). Якщо важливе лише до завершення задачі — це `_ai-tools/BYYOU_PLAN.md`, не ADR.
> **Тримати маленьким.** 1 хвилина на запис. Формат нижче.

---

## Формат (копіюй у новий файл `NNN-коротка-назва.md`)

```markdown
# ADR-NNN: <назва рішення>

**Дата:** DD.MM.YYYY · **Сесія:** XXXXX · **Статус:** прийнято / замінено ADR-MMM

## Проблема
Що вирішували, у якому контексті.

## Варіанти
- A — …
- B — …

## Рішення
Що обрали.

## Чому
Ключові аргументи (1-3).

## Переглянути коли
Умова за якої це рішення варто переглянути (напр. «коли зʼявиться 2-й пристрій»).
```
