# ADR-003: Контекст-запобіжник /byyou (стоп на 75%)

**Дата:** 23.06.2026 · **Сесія:** gfrvu5 · **Статус:** прийнято

## Проблема
У потоці `/byyou` контекст набивається за багато ходів. Ризики: (а) обрив посеред кроку = втрата прогресу; (б) «context anxiety» — модель починає квапливо/неякісно згортати роботу під лімітом; (в) існуючий `context-warning.sh` спрацьовує лише на ввід Романа (UserPromptSubmit), а під час автономного потоку між його повідомленнями — НЕ фіксує. Роман: хоче чіткий стоп на 75% + помітне попередження якого не пропустить серед пульсів.

## Варіанти
- **A — Скіл-правило «я сам звіряю `/cc` щокроку».** Відкинуто: дисципліна на високому контексті деградує; правило-без-автоматики проект уже ловив як провал.
- **B — Stop-хук `exit 0` (лише натяк).** Слабко: показує, але не змушує діяти.
- **C — Stop-хук `exit 2` (блок).** Обрано.

## Рішення
`.claude/hooks/byyou-context-guard.sh` (Stop-подія): під час активного потоку (`BYYOU_PLAN.md` Статус: active) рахує контекст через `lib/compute-context-pct.sh`; при ≥75% — `exit 2` (блокує тихе завершення ходу) + гучний 🛑 на stderr. Розблоковується коли Статус стає `paused`. Дія Claude: дозаповнити «Де зупинились» (handoff) → paused → окреме 🛑 Роману → стоп.

## Чому
- `exit 2` = «loop що не дає згорнутись передчасно» (Anthropic harness practice) — реальний стоп, не натяк.
- 75% лишає запас на чистий handoff (на високому контексті `/finish`/збереження летять — урок SK6E2).
- `BYYOU_PLAN.md` = «explicit progress file» (індустрійний патерн handoff) → новий чат `/byyou` підхоплює з місця. Context reset + structured handoff надійніше за компакцію.
- Сторож сам під dry-run (active→🛑+exit2 / done→тиша) — принцип «хто стереже сторожів» (ADR-002).

## Переглянути коли
Зміна ліміту моделі (зараз `CONTEXT_LIMIT=1_000_000` у compute-context-pct.sh) або якщо 75% виявиться зарано/запізно на практиці.
