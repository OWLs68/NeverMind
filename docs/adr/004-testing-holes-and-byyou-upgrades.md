# ADR-004: Три дірки тестування + прокачка /byyou (26yz5s, 03.07.2026)

## Контекст

Глибоке дослідження двох репозиторіїв (gstack Garry Tan + claude-code-best-practice)
на предмет «що перенести у наш .claude/». Перший прохід шукав «що крутого у них»,
другий (за сигналом Романа «дивись ширше/глибше») — «де у НАС справжні дірки».
Знайдено три системні + пакет нововведень для /byyou.

## Рішення

### 1. 🐤 Канарейка (`canary.yml` + `tests/e2e/canary.spec.js` + `playwright.canary.config.js`)
**Дірка:** E2E бігають ДО злиття; після публікації на Pages живий сайт не перевіряв ніхто —
зламаний деплой першим знаходив Роман телефоном («втрата годин»).
**Рішення:** після Auto-merge → пол бейджа версії до доїзду Pages (макс 5 хв) → WebKit
відкриває прод: UI видимий, 0 JS-падінь, версія свіжа. Fail → GitHub Issue з міткою `canary`.
**Чому не gstack /canary:** їхній двигун = Bun-бінарник + власний CDP-стек; наш Playwright
робить те саме без нових залежностей (принцип «менше = більше»).

### 2. 🤖 AI-смоук (`ai-smoke.yml` + `tests/e2e/ai-smoke.spec.js` + `realAI` у helpers)
**Дірка:** УСІ E2E глушать/мокають OpenAI → поведінку живого AI тестували тільки руки
Романа. А це найбільший шмат його ручного чек-листа.
**Рішення:** 4 наскрізні сценарії з реальним ключем (`OPENAI_SMOKE_KEY`, окремий, ліміт
$5/міс): задача / фінанси / список-чекліст / bareNoun-чіпи. Асерти на СУТНОСТІ (зʼявилась
у вкладці), не на текст AI. Запуск: вручну + щонеділі. Без секрета — тести skip.
**Звʼязок з Хетзнером:** ідея тестування з живим ключем працювала на Hetzner-тестері;
викинули СЕРВЕР (борг+гроші+крихкий CDP), не ідею. CI-запуск за запитом = та сама
цінність без сервера.

### 3. 🔒 Замок DO_NOT_TOUCH (`do-not-touch-guard.js` + `check-dnt-guard.js` 5/5)
**Дірка:** священні корови трималися на чесному слові — той самий клас що «Edit без Read»
до появи pre-edit-read-check.
**Рішення:** PreToolUse Edit|Write у `src/core/boot.js` / `src/app.js` → блок з наказом
прочитати DO_NOT_TOUCH.md; свідомий прохід — фраза `dnt-ack: <файл>` у відповіді
(розблокування до кінця сесії). Список свідомо короткий: замок на все = звикання ігнорувати.

### 4. Прокачка /byyou (з патернів gstack)
- **Хмарний смоук** (скіл `/qa-explore`, Фаза 3 крок 0): Claude сам збирає застосунок,
  клікає зачеплені екрани у Chromium сесії (localhost видно, зовнішні сайти проксі ріже),
  скріншоти+падіння ДО реліз-нотаток. Романові лишаються тільки iOS-специфічні пункти.
- **Верифікатор знахідок** (Фаза 1 крок 3.5, патерн gstack /cso): критична знахідка →
  окремий агент з чистим контекстом пробує СПРОСТУВАТИ. Формалізує «гіпотеза ≠ факт».
- **Памʼять агентів** (`_ai-tools/agent-memory/*.md`): ios-bug-hunter і silent-bug-scout
  читають свою памʼять першою; пише туди ТІЛЬКИ Голова після підтвердження (агенти read-only).
  Нативний frontmatter `memory` не використали — недостатньо контролю хто пише.
- **Sonnet 5 політика** (рішення Романа 03.07, «якість > економія»): `model:"sonnet"` =
  найновіший Sonnet; йому тепер довіряється і верифікація/суддівство, не лише розвідка.
  Код перед Edit читає і пише тільки Голова.

## Відкинуто (і чому)
- Інфраструктура gstack цілком (Bun, телеметрія, авто-апдейт, ML-класифікатор 22МБ) — чужий стек.
- Спринт-скіли (office-hours/CEO-review/design-shotgun) — заміна живого продакта; у нас продакт = Роман.
- /ship, /land-and-deploy, WIP-автокоміти — конфлікт з push-замком /byyou.
- gstack /ios-qa — для нативних Swift-застосунків через USB+Mac; до PWA не застосовний.
- Крос-модельні роутери (best-practice) — залежності заради залежностей; ручний /gemini покриває.

## Наслідки
- Сторожів у CI: 16 node + ESLint + (нове) canary post-deploy + ai-smoke on-demand.
- Ручний смоук Романа стискається до iOS-специфіки.
- Реальний iPhone досі незамінний для ~20% перевірок (гума/PWA/свайпи) — свідомо прийнято.
